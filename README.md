Прототип для хакатона Freedom Broker. Система оценивает работу оператора в чатах и звонках на RU, KZ и EN по настраиваемому чек-листу, показывает доказательства и поддерживает апелляции.

## Запуск

Нужен Python 3.11+.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/uvicorn app.main:app --port 8000
```

Откройте http://localhost:8000.

В `.env` заполните:

- `CQA_API_URL`: GET-ссылка организаторов. В ней есть подпись, поэтому в репозиторий она не попадает.
- `LLM_PROVIDER`: `claude_cli` или `openrouter`.
  - `claude_cli` требует установленный Claude Code с выполненным входом.
  - `openrouter` требует `OPENROUTER_API_KEY`.

## Как пользоваться

1. **Диалоги:** введите `group_id` и нажмите «Загрузить набор», либо загрузите JSON-файл.
2. Выберите чек-лист и запустите оценку.
3. Откройте диалог: баллы, объяснения и переход к реплике или фрагменту записи.
4. Нажмите «Оспорить» у критерия, затем решите апелляцию в разделе **Апелляции**.
5. **Проверка:** ответы, в которых модель не уверена (прогоны разошлись или цитата не найдена), автоматически попадают в очередь. Человек подтверждает или исправляет их, а остальные ответы принимаются без проверки.
6. **Как надо было ответить:** у критерия, где оператор потерял баллы, кнопка показывает ошибку, готовую реплику на языке диалога и правило на будущее. Совет создаётся по запросу и на оценку не влияет.
7. **Чек-лист:** измените критерии и сохраните новую версию. Она применяется при следующей оценке.

Сценарий 5-минутного демо: [docs/demo.md](docs/demo.md). Контрольный этап: [docs/control.md](docs/control.md).

## Как устроено

- `web/`: интерфейс на чистых HTML, CSS и JS. Ему нужны только `#cqa-root`, `styles.css` и `app.js`, а адрес API задаётся через `window.CQA_API_BASE`, поэтому его можно адаптировать как HTML-компонент Dynamics 365.
- `app/main.py`: API на FastAPI и фоновые задачи оценки.
- `app/evaluator.py`: промпт, несколько независимых прогонов, агрегация, проверка цитат.
- `app/review.py`: какие ответы отправлять человеку на проверку.
- `app/coach.py`: совет оператору по проваленному критерию.
- `app/scoring.py`: расчёт итога. Его выполняет код, а не модель: веса, N/A, округление.
- `app/store.py`: SQLite, версии чек-листов, исходная и финальная оценки.

Каждая оценка выполняется заново и сохраняет модель, версию чек-листа, время и стоимость. Готовые результаты не подставляются.

## Модель и стоимость

Основная модель: Claude Sonnet 5.5. По умолчанию выполняются 3 независимых прогона. Для ответов Да/Нет выбирается большинство, для шкал берётся медианная ступень.

На 20 диалогах DEV одна оценка из трёх прогонов стоила в среднем около $0,06 по прайсу. Звонки дороже, до $0,20. Для разработки использовалась подписка Claude, фактическая стоимость на API может отличаться.

Можно переключиться на Claude Opus: `LLM_MODEL=opus`. Один прогон Opus стоил в среднем около $0,07, но он медленнее.
